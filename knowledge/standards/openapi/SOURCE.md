## Where the JSON Schemas actually live

The 3.0.x/3.1.x/3.2.x machine-readable JSON Schema meta-schemas are **not** checked into this repo as static files — they're generated by `scripts/` and published externally at `https://spec.openapis.org/oas/<version>/schema/<date>`, per `.github/workflows/schema-publish.yaml`. Only the **legacy** 1.2 and 2.0 (Swagger) schemas are kept in-repo, under `_archive_/schemas/v1.2/` (multiple files: `resourceObject.json`, `operationObject.json`, `apiDeclaration.json`, etc.) and `_archive_/schemas/v2.0/schema.json` (single-file Swagger 2.0 schema). For 3.x, either fetch the published schema URL directly when strict JSON Schema validation is needed, or rely on the Markdown spec text under `versions/` (the normative source) plus `@nestjs/swagger`'s own bundled OpenAPI 3.x types for code-level validation.

## How the kit should use this

- **API contracts**: write NestJS controllers with `@nestjs/swagger` decorators (`@ApiProperty`, `@ApiOperation`, etc.); the generated document should validate against OpenAPI 3.1 (JSON Schema-compatible `type` unions, `examples`) rather than 3.0 unless a consumer requires 3.0 specifically (some codegen tools still lag on 3.1).
- **Client generation**: point `openapi-typescript` / `orval` / similar at the generated `/api-json` document from the NestJS app, not at this repo directly — this repo is the spec-of-the-spec, not a per-project artifact.
- **Version choice**: default new projects to whatever OpenAPI version `@nestjs/swagger`'s installed version emits (currently 3.0); read `versions/3.1.1.md` or `3.2.1.md` here only when a project explicitly needs 3.1+-only features (e.g. `webhooks`, `type` arrays, JSON Schema 2020-12 alignment).
