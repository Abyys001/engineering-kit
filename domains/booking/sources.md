## Notes

- **`caldiy`**: Not cloned (monorepo, 1.1GB, exceeds practical clone cost for this pass; inspected via raw.githubusercontent.com Prisma schema). Root LICENSE file verified as MIT, 2026-09-26 — the repository's own README states it is 'Cal.diy', a fork of Cal.com with all enterprise/commercial code removed and '100% MIT-licensed, no Open Core split'. This CORRECTS an initial assumption (carried in the task brief) that calcom/cal.com is AGPL: that historically described Cal.com's paid/Enterprise-Edition core, which is not what this repository now contains. Permissive license means it is not marked reference-only for licensing reasons, though nothing was copied — only entity/field names were read from packages/prisma/schema.prisma (EventType, Booking, Attendee, Host, Schedule, Availability, OutOfOfficeEntry, BookingSeat, BookingReference, Payment, Webhook).
- **`easyappointments`**: Not cloned (inspected via raw.githubusercontent.com README + openapi.yml). GPL-3.0 verified from actual LICENSE file. Reference-only, no code copied. Its own OpenAPI contract (openapi.yml) confirms: appointments, availabilities, unavailabilities, customers, services, service_categories, providers, secretaries (a scheduling-on-behalf-of role), working_plan_exceptions, blocked_periods, webhooks. README notes some capabilities (e.g. SMS reminders, deposits) may be gated behind a paid 'premium' tier, not confirmed present in the open-source core — flagged per-feature below.
- **`rfc5545`**: Authoritative standard for calendar events, recurrence rules (RRULE), and time-zone handling; the canonical reference for recurring bookings and calendar sync/export.
- **`wikipedia-no-show`**: General background for no-show policy; used only where not directly evidenced in the two inspected implementations.
- **`pci-dss`**: Same standard already verified for domains/restaurant and domains/hospitality; applies identically to any booking product collecting card deposits/payments.
- **`wikipedia-resource-allocation`**: General background for non-human bookable resources (rooms, equipment); neither Cal.diy nor Easy!Appointments models a generic resource entity.
- **`wikipedia-waiting-list`**: General background for booking waitlists; not present in either inspected implementation.
- **`librebooking`**: GPL-3.0, reference-only: read for its data model over the GitHub API, never copied. A resource-and-schedule booking system independent of the appointment-style tools already cited, which is what makes it a genuine second source. Verified present in the tree: `Domain/Reminder.php`, `Domain/ReminderNotice.php`, `Domain/Access/ReminderRepository.php` and `Jobs/sendreminders.php` (scheduled reminders as a first-class model plus a cron job); `Pages/Ajax/ReservationApprovalPage.php` (an approval step before a booking is confirmed); `Domain/CreditCost.php` (count/cost/currency) with `Domain/Access/CreditRepository.php` and `Pages/Admin/CreditLogPage.php` (money attached to a booking); `Pages/Export/EmbeddedCalendarPage.php` and `Web/export/embedded.php` (an embeddable booking surface); `Domain/Access/ReservationWaitlistRepository.php` with `Jobs/sendwaitlist.php`. It has NO buffer-time concept - `Domain/Blackout.php` is blocked-out time, which is a different thing - and no cancellation-policy model, which is why neither of those features cites it.
