## Notes

- **`karrio`**: reference-only (LGPL). Multi-carrier shipping API/platform. Cloned modules/manager (Address, Parcel, Commodity, Pickup, Tracking, Shipment, DocumentUploadRecord, Manifest models + PickupStatus/ShipmentStatus/TrackerStatus enums in modules/core), and modules/orders (Order model, OrderStatus). The ee/ directory (commercial add-ons, under separate LICENSE_EE) and the rating/providers/connectors modules were not cloned.
- **`fleetbase`**: reference-only (AGPL). Fleet operations / last-mile dispatch platform. Full DB schema inspected via the repo's own generated database.mmd (Mermaid ERD): orders, payloads, waypoints, routes, drivers, vehicles, fleets, manifests, tracking_statuses, issues, maintenance_schedules/maintenances, service_rates/quotes, places, zones. Application code beyond the schema was not deeply inspected in this pass.
- **`gs1-general-specifications`**: Defines the GTIN (product identifier), SSCC (18-digit logistic-unit identifier, printed as a GS1-128 barcode with Application Identifier (00)), and the surrounding AI framework. The GS1 Logistic Label Guideline (a GS1 implementation guideline built on these same GS1-128/SSCC primitives) was checked via its gs1.org landing page for existence but its own version/date could not be fetched directly (403); only General Specifications 26.0 is cited with a verified version.
- **`upu-s10`**: 13-character international postal item identifier (2-letter service indicator + 8-digit serial + check digit + 2-letter ISO country code of the issuing postal operator). Relevant to international parcel/label tracking numbers issued by postal operators rather than integrator carriers.
- **`uncefact-iftmin-ifcsum`**: IFTMIN is the shipper/forwarder-to-carrier transport instruction message for a single consignment (final consignment details, dispatch instruction); IFCSUM is the forwarding/consolidation summary message describing consolidated cargo on a voyage/consignment run. Read via UNECE's own service.unece.org message-directory pages and corroborating summaries, not fetched as a full page in this pass; message existence, purpose and field-level intent are confirmed, exact current release edition is not.
- **`uncefact-mmt-rdm`**: Technical specifications and data structures (subsets, XSDs) for documents accompanying goods moved across sea/inland-water/air/road/rail legs. Corroborates the general shape of multi-leg/multi-stop consignment and transport-plan data, not a route-optimization algorithm. Read via search-indexed UNECE page summaries in this pass, not the full BRS document text.
- **`x12-transportation`**: Corroborated across multiple independent EDI service-provider documentation pages (SPS Commerce, EDI2XML, 1EDISource, EDI Elevate) describing the same four set numbers and the same tender->accept->status->invoice flow. Marked source_type 'secondary' rather than 'authoritative' because the official ASC X12 standard text itself (X12.org) was not accessed.
- **`iata-eawb-cargoxml`**: Air-freight-specific electronic air waybill and the XML messaging standard used between airlines, forwarders, ground handlers, customs and security agencies.
- **`incoterms-2020`**: Standardizes where risk, cost, and delivery/customs responsibility transfer between buyer and seller for a given shipment; used here for the responsibility-transfer dimension of customs and shipment features, never as evidence that a product is legally compliant.
- **`wco-data-model`**: Harmonized customs data elements and packages (goods declaration, AEO mutual recognition, passenger/crew advance information, etc.) used by customs administrations worldwide; cited for the customs-declaration data-modeling dimension of logistics.customs_documents only, not as proof of customs compliance.
- **`adr-2025`**: Road dangerous-goods classification, packaging, marking, labelling, documentation and vehicle/driver requirements across 53 contracting parties.
- **`iata-dgr-67`**: Global reference for classifying, packaging, marking, labelling and documenting dangerous goods shipped by air; the only DG standard recognized by airlines.
- **`imdg-2024`**: Sea dangerous-goods classification, packing, marking and documentation requirements, published in two volumes plus a supplement.
- **`traccar`**: Read only via `gh api` (not cloned to disk), per the research brief's no-new-downloads rule. Open-source GPS/telematics platform (200+ device protocols). Inspected src/main/java/org/traccar/model/{Device,Driver,Position,Geofence,Maintenance}.java: Device/Position carry live telemetry (odometer, engine hours, fuel level/consumption, battery, GPS position); Geofence carries a named boundary with schedule; Maintenance carries name/type/start/period (interval-based service scheduling); Driver is a thin name+uniqueId record. Independent second implementation for vehicle telemetry, geofencing, fuel tracking, and (thinly) driver and fleet-maintenance concepts, alongside fleetbase.
