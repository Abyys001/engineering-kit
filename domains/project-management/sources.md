## Notes

- **`plane`**: reference-only (AGPL). Modern issue-tracking/project-management app (Linear/Jira-like). Cloned apps/api (Django backend) from the `preview` branch. Covers Workspace, Project, Issue (+ Assignee/Label/Comment/Attachment/Relation/Subscriber/Reaction/Version), State/StateGroup, Cycle, Module, Estimate, View, Page, Intake, Notification models.
- **`kanboard`**: Permissive (MIT). A focused, mature kanban board tool (PHP). Full repository cloned (76 MB, under the 200,000 KB threshold). TaskModel/SubtaskModel/ColumnModel/SwimlaneModel/BoardModel/ProjectModel/ProjectRoleModel are the primary references. This is the domain's permissively-licensed source, per the research brief's request to find one where possible.
- **`redmine`**: Inspected via `gh api` (not cloned; GPL-2.0, reference-only). Long-established Ruby on Rails issue tracker. IssueStatus (is_closed flag, default_done_ratio) with per-tracker/per-role WorkflowTransition rules; IssueRelation with TYPE_RELATES/DUPLICATES/DUPLICATED/BLOCKS/BLOCKED/PRECEDES/FOLLOWS/COPIED_TO/COPIED_FROM and explicit reverse-type pairs; Version with VERSION_STATUSES (open/locked/closed) and VERSION_SHARINGS; Project.is_public boolean visibility. OpenProject is a fork of Redmine (via ChiliProject), so the two are NOT treated as fully independent lineages for corroboration counting; noted per-feature where this matters.
- **`openproject`**: Inspected via `gh api` (not cloned; GPL-3.0, reference-only). Full project/portfolio management suite (Ruby on Rails, forked from Redmine via ChiliProject). Status model with workflow transitions; Version (VERSION_STATUSES open/locked/closed, effective_date, sharing); a dedicated `resource_management` module (allocation_step, assignment_candidate, schedule_violation components) for workload/capacity planning; a relation-driven auto-scheduling engine (WorkPackages::ScheduleDependency, DependencyGraph, SetScheduleService) for Gantt date propagation; a dedicated `webhooks` module with outgoing delivery logs; OAuth applications/clients for API access; documented GitHub/GitLab integrations with webhook secrets.
- **`vikunja`**: Inspected via `gh api` (not cloned; AGPL-3.0, reference-only). Go/Vue task manager. Kanban Bucket with a numeric Limit field (WIP limit) and a DoneBucketID; TaskRelation RelationKind (subtask/parenttask/related/duplicateof/duplicates/blocking/blocked/precedes/follows/copiedfrom/copiedto); TaskRepeatMode (default/monthly/from-current-date) with RepeatAfter seconds, applied to the SAME task (reopens it and bumps dates) rather than spawning a new task; IsFavorite per user; SavedFilters; a dedicated Webhook model (target URL, configurable event list, HMAC signing, Basic Auth); a `pkg/caldav` CalDAV server; a `pkg/modules/migration` package with real importers for Trello, Todoist, TickTick, Wekan, Planka, Microsoft To Do, and CSV.
- **`focalboard`**: **Reference-only. The license was recorded as plain MIT in an earlier pass and that was wrong.** Read directly from LICENSE.txt at the pinned ref: the *source code* is licensed under AGPL-3.0 (with a narrow non-enforcement promise) or a commercial license from Mattermost; the MIT grant covers only compiled versions that Mattermost itself produces, and Apache-2.0 covers only the listed admin/config directories. GitHub's API reports NOASSERTION for exactly this reason. Never copy code from it into the kit. Go/TS kanban-board tool (a Trello-like product originally by Mattermost). Board with BoardType (Open/Private) and a block-based content model (BlockType: board/card/view/text/checkbox/comment/image/attachment/divider); a Sharing model exposing a board via an access-token public link, distinct from workspace membership.
- **`leantime`**: Inspected via `gh api` (not cloned; AGPL-3.0, reference-only). PHP project/goal-management tool aimed at non-technical teams. Tickets.statusListSeed defines configurable per-status labels grouped by a `statusType` of NEW/INPROGRESS/DONE (a second, independently-built grouped-status model alongside Plane's StateGroup); Tickets.efforts is a Fibonacci-like point scale (0.5/1/2/3/5/8/13 -> XS..XXL); Tickets.type includes a literal 'milestone' type (a milestone is a Ticket row, with its own getAllMilestones() timeline query, headline, and color) rather than a separate Milestone model; Sprints model (name/startDate/endDate/projectId); Timesheets records hours/description plus independent invoicedEmpl/invoicedComp boolean+date pairs (employee-side vs company-side invoicing), a manual-entry-plus-billing model distinct from Kanboard's timer-based one.
- **`taiga-back`**: Inspected via `gh api` (not cloned; MPL-2.0 per its own LICENSE file -- weak/file-level copyleft, more permissive than AGPL/GPL but not promoted into the kit as permissive). Django/Python agile project-management backend. Epic model (own EpicStatus FK, epics_order, color) distinct from and above user stories; Milestone (Sprint) model with estimated_start/estimated_finish and closed_points/total_closed_points_by_date -- a real burndown-data computation, not just date fields.
- **`scrum-guide-2020`**: The authoritative definition of Scrum. Used only for what it actually specifies: the Sprint as a fixed-length timebox that starts immediately after the previous Sprint ends, Sprint Planning/Daily Scrum/Sprint Review/Sprint Retrospective, Product Backlog refinement (breaking down and adding detail/order/size to backlog items), Sprint cancellation authority, Sprint Backlog/Product Backlog/Increment/Definition of Done. The 2020 edition deliberately dropped prescriptive artifacts like burndown charts, so it is NOT cited as authority for burndown/velocity reporting.
- **`iso-21502`**: General, tool-agnostic project-management terminology (project governance, milestones, schedule, deliverables) used only for the domain's broad framing, not for any tool-specific feature shape -- ISO 21502 does not define kanban, sprints, or any of this domain's software-specific concepts.
- **`pmbok-guide-7`**: General project-management terminology (milestone, schedule, deliverable, stakeholder) used only for domain framing. The 7th Edition is principles-and-performance-domain based, not process-based, and does not define any software-tracker-specific feature.
- **`kanban-method-guide`**: The published definition of the Kanban Method (David J. Anderson): Visualize the workflow, Limit WIP, Manage flow, Make policies explicit, Implement feedback loops, Improve collaboratively/evolve experimentally. Directly grounds this domain's kanban board + WIP-limit capability as an authoritative, not just tool-convention, concept.
- **`rfc6749-oauth2`**: The standard authorization framework third-party integrations (public API access, OAuth apps) commonly use; OpenProject implements OAuth applications/clients for its API, cited alongside this RFC rather than as a substitute for it.
- **`rfc4791-caldav`**: The standard protocol for calendar sync; Vikunja implements a CalDAV server (pkg/caldav) that this domain's calendar_sync integration is modeled on.
