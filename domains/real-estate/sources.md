## Notes

- **`openproperty`**: Not cloned; inspected via GitHub API (root LICENSE file confirms MIT). Reference-only, extraction-safe if cloned later. Self-hosted rental property management (TenantCloud/AppFolio/Buildium alternative): units, tenants, leases, rent collection, maintenance work orders (`src/server/schema.sql`, `src/client/components/{tenants,leases,maintenance}`).
- **`movinin`**: Not cloned; inspected via GitHub API (root LICENSE file confirms MIT). Reference-only. MERN-stack property rental platform with mobile app: `backend/src/models/{Property,Booking,Location,User}.ts` — confirms property type enum (House/Apartment/Townhouse/Plot/Farm/Commercial/Industrial) and a booking(lease)-style status lifecycle (Void/Pending/Deposit/Paid/Reserved/Cancelled).
- **`easy-property-listings`**: Not cloned; inspected via GitHub API (`license.txt` confirms GPL-2.0). Reference-only (GPL). Mature real-estate-agency-specific listing plugin: post types for property/rental/land/commercial/business/contact (agent) confirm the sales-vs-rental listing split and an agent/contact entity distinct from the property-management-focused sources above.
- **`reso-data-dictionary`**: Industry-standard field/entity vocabulary (Property, Member, Office, OpenHouse, etc.) used by North American MLS systems. This session's sandboxed network blocked a live re-fetch of reso.org, so this is cited from well-established prior knowledge at medium confidence rather than high. Not to be confused with `NationalAssociationOfRealtors/reso-data-dictionary` on GitHub, which is a thin MIT-licensed OData client wrapper, not the dictionary itself.
- **`schema-org-real-estate`**: Structured-data vocabulary for listing search-engine markup (RealEstateListing, Offer, Residence/Apartment/SingleFamilyResidence types). Live re-verification failed in this sandbox (network/TLS restrictions); treated as well-established from training knowledge.
