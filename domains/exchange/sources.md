## Notes

- **`bdc-api`**: Hobby-scale (1 star) TypeORM/Express API for a bureau de change: currency, daily_rate (buy/sell, official/market), purchase/purchasemain (buy transactions with cash-note serial ranges), selling (sell transactions with transaction_ref, buyingrate/soldrate, KYC fields mode_of_id/id_no/id_expirydate/bvn), users. Inspected via `gh api repos/.../contents` (not cloned; no license to extract under). Single implementation — evidence held at low/medium confidence per feature, never 'industry standard' on its own.
- **`chfx-odoo-modules`**: Odoo addon modules (`exchange_counter`, `chfx_extension`) with real fields for exchange.branch, exchange.counter (till, linked to an accounting journal and per-currency cash accounts), exchange.session (cashier session on a counter), exchange.transaction (buy/sell with mid_rate vs used_rate vs manual_rate, margin_pct, commission, KYC required/confirmed flags, partner/client link, accounting move), exchange.rate, exchange.remittance. Inspected via `gh api repos/.../contents` (not cloned). Second independent implementation — corroborates branch/counter/session/rate/transaction/remittance as real, separately-modeled concepts.
- **`fatf-recommendations`**: Recommendation 20 (suspicious transaction reporting) and the customer due diligence recommendations directly govern money-or-value-transfer services and currency exchange offices as 'obliged entities' / DNFBPs in most jurisdictions.
- **`iso4217`**: Currency code terminology for buy/sell rate pairs and cash positions.
- **`iso20022`**: Cross-border remittance/payment messaging terminology, used when an exchange house settles or receives via bank rails.
- **`eu-amld`**: Currency exchange offices are named obliged entities under EU AML law; cited generically — no jurisdiction-specific (e.g. Iranian) rule is asserted anywhere in this domain.
- **`blnk`**: On-disk clone (see sources/domains/blnk/SOURCE.md). Real double-entry ledger with explicit Transaction, Balance, Identity, and a standalone reconciliation.go engine (reconciliation_matching_test.go, reconciliation_rules_test.go) plus transaction_refunds.go/transaction_refund.go modelling refund as a first-class reversal of a posted transaction. Not bureau-de-change-specific, but a real, on-disk, Apache-2.0 implementation of settlement reconciliation and transaction refund/reversal as domain concepts in a financial ledger.
- **`moov-io-watchman`**: Inspected via `gh api` (not cloned). Actively maintained, production-used open-source sanctions/PEP screening engine: ingests OFAC SDN/Non-SDN, US CSL, FinCEN 311, EU/UK/UN consolidated lists and OpenSanctions data, scores each candidate 0-1 with an inspectable multi-field matcher (name, alias, government ID, DOB, address). Concretely evidences exchange.sanctions_screening and the sanctions_watchlist_screening integration as a real, separately-built concern distinct from generic identity verification.
- **`moov-io-customers`**: Inspected via `gh api` (not cloned). A customer registry purpose-built for KYC/Customer Identification Program plus OFAC checks; its own docs (docs/watchman.md) and migrations (create_customer_ofac_searches, create_account_ofac_searches) show identity verification and sanctions screening modelled as linked but distinct concerns, corroborating the same split used in this domain's exchange.kyc_thresholds vs exchange.sanctions_screening.
- **`moov-io-ach`**: Inspected via `gh api` (not cloned). Real, actively maintained reader/writer/validator for US ACH bank-transfer files; evidences the bank_transfer_rail integration as a concrete, separately-implemented concern.
- **`moov-io-iso20022`**: Inspected via `gh api` (not cloned). Open-source implementation of ISO 20022 message parsing/generation; corroborates the iso20022 authoritative source with a concrete implementation for the bank_transfer_rail integration.
- **`pci-dss`**: Governs any card acquiring/card-funded flow an exchange business adds on top of its cash/bank-transfer core.
- **`eu-tfr-2023-1113`**: Implements FATF Recommendation 16 in the EU: requires complete originator/beneficiary information to accompany a transfer of funds. Directly relevant to exchange.remittance and any bank-rail settlement leg.
- **`fincen-msb`**: US currency dealers/exchangers and money transmitters must register with FinCEN as MSBs and maintain an agent list. Cited generically for the US as one jurisdiction's implementation of the obliged-entity concept, not as a universal rule.
- **`hmrc-msb-guidance`**: UK currency exchange, money transmission, and cheque-cashing businesses register with HMRC under MLR 2017 (or need separate FCA authorisation for payment services). Cited generically for the UK, not as a universal rule.
- **`wolfsberg-correspondent-banking`**: Industry (non-binding) due-diligence principles relevant when an exchange/remittance business relies on a correspondent bank or network partner to settle cross-border transfers.
- **`apache-fineract`**: Apache-2.0 core banking platform, read over the GitHub API (not cloned). Not a bureau de change, but it models the branch-counter mechanics this domain shares with any cash-handling financial institution, which is what makes it a genuine second source rather than an analogy: `organisation/teller/domain/` has Teller (with its own TellerStatus enum), Cashier, CashierTransaction, CashierTxnType and TellerJournal — a till allocated to a named cashier with audited cash in/out; `organisation/office/domain/Office.java` plus OfficeTransaction — hierarchical branches with inter-branch transfers; `organisation/staff/domain/Staff.java` with StaffOrganisationalRoleType; `portfolio/charge/domain/ChargeCalculationType.java` — FLAT vs PERCENT_OF_AMOUNT, exactly the flat-fee-or-percentage commission choice; `fineract-command-audit/` — audit implemented as before/after/error command hooks; `infrastructure/dataqueries/domain/Report.java` with ReportType and a reportmailingjob scheduler. It has no FX rate feed and no remittance, which is why neither of those features cites it.
