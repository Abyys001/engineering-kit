## Notes

- **`frappe-hospitality`**: Reference-only (GPL-3.0). ERPNext hotel module: Hotel Room, Hotel Room Type, Hotel Room Amenity, Hotel Room Pricing (+Item/Package), Hotel Room Reservation (+Item), Hotel Settings doctypes. Shared with domains/restaurant.
- **`qloapps`**: Not cloned (inspected via gh api git tree + raw.githubusercontent.com; 132MB repo, PrestaShop e-commerce core + hotelreservationsystem module). OSL-3.0 verified from actual LICENSE.md — a network/external-deployment copyleft license (section 5), treated with the same caution as AGPL: reference-only, no code copied. modules/hotelreservationsystem/classes/ has ~35 Hotel*/RoomType*/ServiceProduct* classes covering branches, room types, rooms, feature-based rate pricing + restrictions, booking detail + status history (Assigned/CheckedIn/CheckedOut/NoShow/Cancelled), advanced payment, refund rules, connected rooms, channel manager + ARI (Availability-Rate-Inventory) webservice, add-on service products, and PDF booking vouchers.
- **`opentravel-alliance`**: Verified organizational facts and access status only (public mirror stops at 2017B; the OpenTravel site's download form lists newer releases behind registration). Did not obtain and read the full current message schema text in this pass, so this source is NOT treated as sufficient alone for 'high' confidence on any feature — cited for terminology (e.g. OTA_HotelResRQ/RS, availability/rate/inventory message families) that is independently well documented in secondary literature, not for message-level detail.
- **`htng`**: Verified via secondary reporting (Hospitality Technology, AltexSoft, Wikipedia) that HTNG is still active and that its interfaces frequently carry OpenTravel message payloads; did not access gated specification text directly. Cited for the channel-manager/PMS-interface concept only, at low/medium confidence.
- **`pci-dss`**: Card payment security standard; applies to any property accepting card payments or deposits.
- **`eu-gdpr`**: EU-jurisdiction personal data protection requirement for guest profile data (identity documents, contact details, stay history).
- **`wikipedia-night-audit`**: General background for the night-audit process; not found in either inspected implementation.
- **`wikipedia-housekeeping`**: General background for housekeeping/room-turnover status tracking; not found in either inspected implementation as a dedicated module.
- **`wikipedia-yield-management`**: General background for demand-based dynamic pricing, distinct from the rule/season-based rate plans both implementations have.
- **`wikipedia-loyalty-program`**: General background for guest loyalty/rewards; not present in either inspected implementation.
- **`wikipedia-customer-review`**: General background for guest review collection; not present in either inspected implementation.
- **`wikipedia-hotel`**: General background only; no single authoritative cross-jurisdiction source on guest ID/passport registration requirements was found in this pass.
