## Notes

- **`nextcrm`**: Verified full LICENSE file: plain MIT, no exceptions. Rich Prisma schema (~90 models). Confirmed models: crm_Contacts, crm_Accounts (with member_of parent-account field), crm_Leads (lead_source/status/type lookups, assigned_accounts FK, no explicit convert action found), crm_Opportunities + crm_Opportunities_Sales_Stages + crm_OpportunityLineItems + approval_status workflow (quote/SOW approval before sending), crm_FunnelSettings (kill/recycle/cadence-touch follow-up timers), crm_Activities + Tasks (polymorphic activity links), crm_Products/crm_ProductCategories/crm_AccountProducts, crm_Targets/crm_TargetLists (segmentation, tags, do-not-email), crm_campaigns, crm_Report_Config/crm_Report_Schedule, EmailAccount/Email (IMAP/SMTP sync), CalendarConnection/crm_CalendarEvents (Google OAuth). Confirmed CSV import for products (actions/crm/products/import-products.ts) and targets (actions/crm/targets/import-targets.ts), not contacts specifically. Copy-safe.
- **`espocrm`**: AGPL-3.0, reference-only. Read over the GitHub API: `application/Espo/Modules/Crm/Resources/metadata/entityDefs/Lead.json` — `status` options are exactly ['New','Assigned','In Process','Converted','Recycled','Dead'], plus `convertedAt` and `createdAccount`/`createdContact`/`createdOpportunity` links, which is direct evidence for the lead state machine and for conversion producing three records; `Opportunity.json` — `stage` options ['Prospecting','Qualification','Proposal','Negotiation','Closed Won','Closed Lost']; `assignedUser` field. Notably its core has NO Quote, Product, Report or Workflow entityDef (those are the paid Advanced Pack), so Espo is deliberately NOT cited for those features.
- **`odoo-crm`**: LGPL-3.0 per addon manifest, reference-only. Read over the GitHub API at branch 18.0: `addons/crm/models/crm_lead.py` (`type` lead/opportunity selection, `date_conversion`, `stage_id`, `user_id`, `team_id`, `probability`, `lost_reason_id`), `addons/crm/models/` listing (`crm_team.py`, `crm_team_member.py`, `crm_lead_scoring_frequency.py`, `crm_stage.py`), `odoo/addons/base/models/res_partner.py` (`parent_id` 'Related Company' + `child_ids` + `commercial_partner_id` — the account hierarchy), and the presence of the `sale` (with `sale_order.py`/`sale_order_line.py`), `base_automation`, `base_import`, `board`, `spreadsheet_dashboard`, `google_calendar`, `microsoft_calendar` and `mass_mailing` addons.
- **`suitecrm`**: AGPL-3.0, reference-only: read for its data model, never copied. `salesagility/SuiteCRM` redirects to `SuiteCRM/SuiteCRM`. Read over the GitHub API (not cloned): `modules/` listing, `modules/Accounts/vardefs.php` (`parent_id` + `member_of` account hierarchy), `modules/Leads/vardefs.php` (`converted` flag, comment 'Has Lead been converted to a Contact'), `include/SugarObjects/implements/assignable/vardefs.php` (`assigned_user_id` on every assignable module). The AOS_* modules (Quotes, Products, Products_Quotes, Line_Item_Groups, Invoices, Contracts, PDF_Templates), AOR_* reporting modules, and AOW_* workflow modules are in core, which is what makes quotes, line items, reporting and automation corroborated rather than assumed.

Read over the GitHub API: `packages/twenty-server/src/modules/{person,company,opportunity,note,task}/standard-objects/*.workspace-entity.ts` — a modern CRM that still ships exactly person, company, opportunity, note and task as standard objects, with `note-target`/`task-target` join entities behind the activity timeline.
